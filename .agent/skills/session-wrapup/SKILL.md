# 🏁 Session Wrap-Up & Handover Skill (ทักษะขั้นตอนการจบการสนทนาและการปิดเซสชัน)

ทักษะมาตรฐานสำหรับขั้นตอนการ **"จบการสนทนา" (Session Wrap-Up)** เพื่อตรวจรับความเรียบร้อยของโค้ด สรุปผลงาน บันทึกประวัติลง Git ด้วยภาษาไทย อัปเดตสถานะใน ClickUp และจัดเตรียมแผนส่งต่องานสำหรับรอบการทำงานถัดไปอย่างมืออาชีพ

---

## ⏰ เงื่อนไขการเปิดใช้งานทักษะ (When to Activate)

เปิดใช้งานทักษะนี้ทันทีเมื่อผู้ใช้ส่งข้อความในลักษณะ:
* *"จบการสนทนา"* / *"จบสนทนา"*
* *"ปิดงานวันนี้"* / *"เลิกงานแล้ว"*
* *"วันนี้พอแค่นี้ก่อน"*
* *"wrap up เซสชัน"* / *"สรุปปิดงาน"*
* หรือเมื่อถึงเวลาสิ้นสุดการทำงานประจำวัน (17:30 น.)

---

## 📋 ระเบียบวิธีปฏิบัติ 5 ขั้นตอน (5-Step Closing Protocol)

เมื่อผู้ใช้ส่งสัญญาณจบการสนทนา Agent จะต้องปฏิบัติตามลำดับขั้นตอนดังนี้อย่างเคร่งครัด:

```
[1. ตรวจสอบ Git & เตรียม Commit ภาษาไทย] 
             ⬇
[2. ตรวจสอบสถานะการ Build & รันระบบ]
             ⬇
[3. อัปเดตสถานะงานบน ClickUp]
             ⬇
[4. สร้างรายงานสรุปประจำวัน (Word & Markdown)]
             ⬇
[5. ส่งมอบข้อความสรุปปิดเซสชันและแผนงานรอบถัดไป]
```

---

### ขั้นตอนที่ 1: ตรวจสอบ Git และเสนอ Commit Message ภาษาไทย

1. รันคำสั่ง `git status` เพื่อตรวจสอบไฟล์ที่ถูกแก้ไข (Modified) และไฟล์ที่ยังไม่ได้ Track (Untracked)
2. สรุปรายการไฟล์สำคัญที่สร้างหรือแก้ไขในเซสชันนี้ให้ผู้ใช้เห็น
3. **จัดทำ Commit Message เป็นภาษาไทย (UTF-8)** ตามรูปแบบมาตรฐานที่ผู้ใช้กำหนด:
   * **รูปแบบแนะนำ (Standard Conventional + Thai)**:
     * `feat(<module>): <คำอธิบายฟีเจอร์ภาษาไทย> (Sprint X)`
     * `fix(<module>): <คำอธิบายการแก้บักภาษาไทย>`
     * `docs(<module>): <คำอธิบายการอัปเดตเอกสารภาษาไทย>`
     * `refactor(<module>): <คำอธิบายการปรับโครงสร้างโค้ดภาษาไทย>`
   * **ตัวอย่างจริง**:
     * `feat(attendance): เพิ่มระบบจัดการกะการทำงานและคำนวณผ่อนปรนเวลา (Sprint 3)`
     * `docs(schema): ปรับปรุงเอกสารพจนานุกรมข้อมูล 77 ตารางเป็น 3 คอลัมน์พร้อมย่อหน้า Tab`
4. ดำเนินการ `git add .` และ `git commit -m "..."` พร้อม `git push -u origin <branch>` หากผู้ใช้อนุมัติ
5. ระบุสถานะ Pull Request (PR) หรือแนะนำขั้นตอนการรวมโค้ดเข้าสู่กิ่งหลัก `master`

---

### ขั้นตอนที่ 2: ตรวจสอบความสมบูรณ์ของระบบ (Build & Health Check)

ตรวจเช็คให้แน่ใจว่างานที่ทำไม่ทำให้ระบบพังก่อนปิดเซสชัน:
1. **Backend (.NET API)**: รัน `dotnet build backend/src/Hrms.Api/Hrms.Api.csproj` ต้องได้ `0 Error(s)`
2. **Frontend (Next.js)**: รัน `npm run build` ในโฟลเดอร์ `frontend/` ต้องผ่านและคอมไพล์สำเร็จทุกเส้นทาง
3. **กฎ 10 ข้อ (Engineering Rules)**:
   * ทุกตารางในหน้าเว็บต้องมี `whitespace-nowrap` ไม่ขึ้นบรรทัดใหม่
   * ข้อความ UI ต้องเป็นภาษาไทย 100% ไร้วงเล็บภาษาอังกฤษปน

---

### ขั้นตอนที่ 3: ซิงค์สถานะงานบน ClickUp (Task Status Synchronization)

1. ตรวจสอบงานที่กำลังทำอยู่ใน ClickUp (เช่น Phase 1, Phase 2, Phase 3)
2. หากงานใน Sprint นั้นเสร็จสมบูรณ์และทดสอบผ่านแล้ว:
   * ปรับสถานะจาก `IN PROGRESS` ➔ `COMPLETE`
3. อัปเดต Task ถัดไปที่เตรียมทำในวันถัดไปให้อยู่ในสถานะพร้อมเริ่มทำงาน

---

### ขั้นตอนที่ 4: สร้างรายงานสรุปประจำวัน (Daily Progress Report)

1. รันการสรุปผลงานผ่านทักษะ `daily-progress-reporter`
2. สร้างเอกสารรายงานทั้ง 2 รูปแบบ บันทึกไว้ในโฟลเดอร์ `daily_reports/`:
   * `{N}.daily_summary_{YYYY-MM-DD}.md`
   * `{N}.daily_summary_{YYYY-MM-DD}.docx` (เอกสาร Word จัดหน้าสวยงาม ฟอนต์ TH Sarabun New)

---

### ขั้นตอนที่ 5: สรุปปิดท้ายและส่งมอบงาน (Closing & Handover Message)

ส่งข้อความสรุปปิดเซสชันในแชตอย่างสุภาพ เป็นกันเอง และชัดเจน โดยมีโครงสร้างดังนี้:
1. **🎉 สรุปผลงานที่ทำสำเร็จในเซสชันนี้**: สิ่งที่พัฒนาเสร็จเรียบร้อยและสถานะของระบบ
2. **📦 สถานะ Git & ClickUp**: หมายเลข Commit, กิ่งที่ทำงาน, ลิงก์ PR, และสถานะบน ClickUp
3. **📄 ลิงก์เอกสารและรายงานประจำวัน**: ชี้เป้าหมายไฟล์รายงานในโฟลเดอร์ `daily_reports/`
4. **⏩ แผนงานที่จะเริ่มทำต่อในเซสชันหน้า (Next Session Action Items)**: 2-3 ข้อชัดเจน เพื่อให้เมื่อกลับมาเปิดแชตใหม่ สามารถพิมพ์เริ่มงานต่อได้ทันที
5. **คำอวยพรปิดท้ายเซสชัน**: อวยพรให้พักผ่อนอย่างมีความสุข
