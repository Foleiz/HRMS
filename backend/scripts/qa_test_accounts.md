# บัญชีทดสอบ (QA) — สร้างเมื่อ 7 ต.ค. 2569

สร้างผ่านหน้า/API ตั้งค่าผู้ใช้งาน (POST /api/users) ด้วยบัญชี admin และทดสอบล็อกอินผ่านแล้วทุกบัญชี
ใช้สำหรับทดสอบในเครื่องเท่านั้น — ลบหรือปิดบัญชีเหล่านี้ก่อนขึ้นใช้งานจริง

| ชื่อผู้ใช้ | บทบาท (role) | พนักงาน | แผนก / ตำแหน่ง |
|---|---|---|---|
| test.finance | PAYROLL_ADMIN | EMP0014 ปุก | แผนกบัญชี / ธุรการ (บัญชี) |
| test.lead | LINE_MANAGER | EMP0021 คุณเอิร์ท | แผนกพัฒนาซอฟต์แวร์ / หัวหน้าทีมพัฒนาซอฟต์แวร์ |
| test.employee | TEST01 (ESS) | EMP0011 แบงค์ | แผนกพัฒนาซอฟต์แวร์ / วิศวกรซอฟต์แวร์ |
| test.employee2 | TEST01 (ESS) | EMP0012 มีน | แผนกพัฒนาซอฟต์แวร์ / วิศวกรซอฟต์แวร์ |

รหัสผ่านอยู่ใน frontend/.env.local → NEXT_PUBLIC_DEMO_ACCOUNTS (ไม่อยู่ใน git) แผง "บัญชีสำหรับทดสอบ" หน้า login อ่านจากค่านี้ (เฉพาะโหมด dev)

หมายเหตุ: test.lead จะเห็นคำขอให้อนุมัติก็ต่อเมื่อสายการอนุมัติ (ตั้งค่า → สายการอนุมัติ)
ชี้มาที่หัวหน้าทีม/ผู้บังคับบัญชาของ test.employee

## สายการอนุมัติคำขอลาของ test.employee (จำลองเมื่อสร้างบัญชี)
1. หัวหน้างานโดยตรง — ยังไม่ได้ตั้งหัวหน้าให้ EMP0011/EMP0012 (ระบบจะข้ามไปตาม fallback)
2. ฝ่ายบุคคล — EMP0002 (hr)
3. CEO — EMP0003 (job) — ตั้งรหัสแล้ว 27 ต.ค. 2569 (ผู้ใช้ตั้งเอง ไม่ได้บันทึกรหัสไว้ที่นี่)

หมายเหตุ: test.employee / test.employee2 ใช้บทบาท TEST01 แทน EMPLOYEE เพราะบทบาท EMPLOYEE ในฐานข้อมูลตอนนี้
ไม่มีสิทธิ์ ESS_DOCS / ESS_LEAVE / ESS_PROFILE / ESS_TIME / ESS_NEWS (ยื่นเอกสาร/ยื่นลาไม่ได้)
แต่กลับมีสิทธิ์ดูเมนูฝั่ง HR หลายเมนู — ควรให้ผู้ดูแลระบบตั้งค่าบทบาท EMPLOYEE ใหม่
